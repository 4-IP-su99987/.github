<p>这篇只讲服务器侧，四个地址怎么在操作系统里落地、路由和网卡怎么设置、服务怎么绑定到指定地址，以及怎么验证绑定是否生效。</p>
<h2>一、服务器视角下的四个地址</h2>
<p>对服务器来说，四个公网地址就是四张网卡上的四组配置，或者一张网卡上的四组别名。操作系统不关心它们从哪来。</p>
<p>分配的核心问题是：哪个服务用哪个地址。服务绑定地址以后，外部访问哪个地址就进哪个服务，互不干扰。</p>
<p>如果不做绑定，服务默认监听全部地址，四个地址都能访问同一个端口，日志里也分不清请求从哪进来。</p>
<h2>二、网卡与别名的写法</h2>
<p>一张网卡追加多个地址用别名，命名上按顺序编号。写进配置文件后重启网络服务，别名会随网卡一起起来。</p>
<p>不要用临时命令配置生产地址，重启就丢。临时命令只适合验证阶段，验证完立刻写进配置文件。</p>
<h3>配置文件注意什么</h3>
<p>每个地址一段配置，掩码和网关只在主地址上写一次。别名上重复写网关会导致路由冲突。</p>
<p>改完配置文件先做语法检查，再重启服务。直接重启出错的配置会让服务器失联，远程操作时尤其危险。</p>

<h2>三、服务绑定到指定地址</h2>
<p>Web 服务在配置里写监听地址，把地址换成具体的公网地址，端口保持不变。四个地址可以各起一个实例。</p>
<p>数据库和缓存服务建议只绑内网地址，不要绑公网。公网地址留给必须对外的服务，暴露面越小越好。</p>
<p>绑定后重启服务，用外部地址访问测试。访问不通先看监听状态，再看防火墙，最后看上游映射。</p>
<h3>怎么确认监听正确</h3>
<p>查看监听列表，确认每个地址的端口都在监听，且没有多余的零地址监听。零地址监听意味着所有地址都能进。</p>
<p>如果发现服务监听在零地址上，说明配置没生效或者有多份配置。检查配置加载顺序，别只改一处。</p>
<h2>四、路由与策略</h2>
<p>默认路由只有一条，指向网关。四个地址共用这条路由，流量从哪个地址出去由源地址决定。</p>
<p>需要指定出口时用策略路由，按源地址匹配，指定从某个地址发出。规则写在路由表里，重启后要能自动加载。</p>

<h2>五、防火墙与端口</h2>
<p>四个地址的防火墙规则要分开写，不要用一条规则覆盖全部地址。分开写以后，哪个地址开放了什么一目了然。</p>
<p>对外只开放必要端口，管理端口限制来源地址。规则顺序从上到下匹配，范围小的放前面。</p>
<p>修改防火墙前先确认还有一条可用的登录通道，避免把自己挡在外面。远程操作时这条尤其重要。</p>
<h3>端口冲突怎么处理</h3>
<p>同一个端口在不同地址上可以各自监听，不算冲突。冲突只会发生在同一地址同一端口上。</p>
<p>如果两个服务要用同一地址的同一端口，只能改端口或者加反向代理。改端口最直接，加代理更灵活。</p>
<h2>六、验证与交付</h2>
<p>验证清单：四个地址都能 ping 通、每个地址的监听正确、外部访问能进到对应服务、防火墙规则符合预期。</p>
<p>验证完成后把配置、监听列表和防火墙规则导出留档。下次改动能快速对比，减少误改。</p>
<p>交付时写一页说明，讲清地址与服务的对应关系。这一页纸能省掉后来人大量摸索时间。</p>
<h2>常见问答</h2>
<h3>四个地址必须配在同一张网卡上吗？</h3>
<p>答：不必，可以分在多张网卡上，主要看服务器网卡数量和上游交换机的端口规划。</p>
<h3>别名地址重启后会丢失吗？</h3>
<p>答：写进配置文件不会丢，用临时命令配的会丢，生产环境一律写配置文件。</p>
<h3>服务能同时监听四个地址吗？</h3>
<p>答：可以，分别绑定或者监听全部地址都行，分别绑定更利于按地址区分流量。</p>
<h3>改配置导致服务器失联怎么办？</h3>
<p>答：提前保留带外管理或者控制台通道，通过控制台回滚配置，不要在失联状态下反复重启。</p>
